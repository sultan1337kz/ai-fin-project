# 00 — Настройка проекта

## 1. Что делает модуль

Это фундамент: менеджер зависимостей, структура пакета, линтер, проверка типов, тесты, локальный Postgres и CI. Бизнес-логики нет. Место в пайплайне — «под» всеми этапами: каждый следующий модуль (парсеры, матчер, MCP-серверы, агент) просто добавляет код в `src/recon/<модуль>/` и тесты в `tests/`, а CI автоматически прогоняет `ruff → mypy → pytest` на каждый push.

## 2. Ключевые концепции

### uv vs pip / Poetry (и сравнение с Maven/Gradle)

| Задача | Java | pip | Poetry | uv |
|---|---|---|---|---|
| Описание проекта | `pom.xml` / `build.gradle` | `requirements.txt` (только список) | `pyproject.toml` (свой формат `[tool.poetry]`) | `pyproject.toml` (стандарт PEP 621 `[project]`) |
| Lock-файл | нет по умолчанию (`dependencyManagement`, Gradle lockfiles) | нет (`pip freeze` — вручную) | `poetry.lock` | `uv.lock` |
| Изоляция зависимостей | `~/.m2` + classpath на проект | `venv` создаёшь сам | создаёт venv | создаёт `.venv` автоматически |
| Версия рантайма | toolchains / SDKMAN | ставишь Python сам | ставишь Python сам | `uv python install`, `.python-version` |
| Скорость | — | медленно | медленно | очень быстро (Rust, глобальный кэш) |

Главное отличие от Java: в Python **нет classpath на уровне сборки**. Зависимости ставятся в виртуальное окружение (`.venv/`) — отдельную копию интерпретатора со своей папкой `site-packages`. `uv run <cmd>` = «выполни команду внутри `.venv` проекта, предварительно синхронизировав его с `uv.lock`». Ближайшая аналогия — `mvn exec:java`, который сам гарантирует правильный classpath.

`uv sync --locked` в CI: падает, если `uv.lock` не соответствует `pyproject.toml`. Это защита от «у меня работает»: в CI ставятся ровно те версии, что закоммичены.

### Структура Python-пакета (src layout)

```
src/recon/__init__.py      # recon — пакет (≈ Java package, но это ещё и модуль-объект)
src/recon/parsers/__init__.py
src/recon/py.typed         # маркер PEP 561: «у пакета есть аннотации типов»
```

- **`__init__.py`** делает папку пакетом. В Java пакет — это просто путь; в Python пакет — объект, который исполняется при первом `import`. Код в `__init__.py` выполняется один раз (как static-инициализатор класса).
- **Почему `src/`?** Без неё (`recon/` в корне) Python при запуске из корня репозитория найдёт пакет в текущей директории, а не установленный. Тесты пройдут, а собранный wheel может оказаться битым (забыли файл, неверный `package-data`). С `src/` тесты импортируют только *установленный* пакет (`uv sync` ставит его в editable-режиме — аналог того, что IDE подкладывает `target/classes` в classpath).
- `data/generator` и `evals/` лежат вне `src/` — это инструменты репозитория, не часть поставляемого пакета. `python -m data.generator` работает, потому что `-m` добавляет текущую директорию в `sys.path`.

### pyproject.toml

Единый конфиг, как `pom.xml`:
- `[project]` — имя, версия, `requires-python`, runtime-зависимости (`<dependencies>` со scope compile).
- `[dependency-groups] dev` — инструменты разработки (≈ `<scope>test</scope>` / `testImplementation`). В продакшн-образ не попадают.
- `[build-system]` — чем собирать wheel (≈ какой plugin делает jar). У нас `uv_build`.
- `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]` — настройки инструментов в одном файле (в Java это были бы `checkstyle.xml`, `spotbugs`-конфиги, `surefire` в pom).

### Зачем mypy в Python

Python проверяет типы **только в рантайме и только когда операция уже выполняется**. Аннотации (`def f(x: Decimal) -> Money`) интерпретатор игнорирует. mypy — внешний статический анализатор, который делает то, что в Java делает `javac`: находит `None` там, где ждут значение, `float` вместо `Decimal`, неверные аргументы — до запуска.

`strict = true` включает, среди прочего:
- обязательные аннотации у всех функций (`disallow_untyped_defs`);
- запрет неявного `Any` из нетипизированных вызовов;
- проверку `Optional` (аналог того, что в Java дал бы `@NonNull` + строгий анализатор).

Для денежного кода это критично: ошибка «передали `float` в расчёт суммы» должна ловиться в CI, а не в сверке.

### ruff

Линтер + форматтер в одном (заменяет flake8, isort, black, pyupgrade). Аналог Checkstyle + Spotless. Правило `B` (bugbear) ловит типичные ловушки Python — например, изменяемое значение по умолчанию `def f(x=[])`.

## 3. Python-особенности

- **Виртуальное окружение** вместо classpath (см. выше).
- **`python -m package`** — запуск пакета как программы (исполняется `package/__main__.py`), аналог `java -cp ... Main`.
- **Аннотации типов не проверяются интерпретатором** — только mypy.
- **pytest находит тесты по соглашению**: файлы `test_*.py`, функции `test_*`. Никаких аннотаций `@Test`; проверка — обычный `assert` (pytest переписывает его, чтобы показать значения при падении).
- **Exit code 5 у pytest** = «ни одного теста не найдено». Поэтому есть `tests/test_smoke.py` — иначе пустой CI падал бы.

## 4. Альтернативы

- **Poetry** — зрелый, но медленный, свой формат секций и не управляет версиями Python. Отклонено.
- **pip + requirements.txt** — нет нормального lock-файла и разделения dev/prod. Отклонено.
- **Flat layout** — проще, но маскирует ошибки упаковки. Отклонено.
- **pyright вместо mypy** — быстрее, лучше в IDE; mypy выбран как де-факто стандарт, который чаще ожидают увидеть на ревью. Можно пересмотреть.
- **hatchling / setuptools как build backend** — работают, но `uv_build` не требует отдельного инструмента и конфигурации для src layout.
- **Postgres 18** — новее, но изменил путь хранения данных в образе; закрепили 17, чтобы не ловить сюрпризы с volume.

## 5. Что может сломаться

| Симптом | Причина |
|---|---|
| CI: `The lockfile at uv.lock needs to be updated` | Изменили `pyproject.toml`, не запустили `uv lock` / `uv sync` и не закоммитили `uv.lock`. |
| `ModuleNotFoundError: No module named 'recon'` | Запуск не через `uv run` (системный Python без `.venv`), или проект не установлен — `uv sync`. |
| mypy: `Skipping analyzing "xyz": module is installed, but missing library stubs` | У библиотеки нет типов. Ставим `types-xyz` или делаем override для одного модуля. |
| pytest: `no tests ran`, exit 5 | Тестов нет или неверный `testpaths`/имена файлов. |
| `docker compose up`: Postgres не стартует, в логах `POSTGRES_PASSWORD is not specified` | Нет `.env` — скопировать из `.env.example`. |
| Порт 5432 занят | Локальный Postgres уже запущен — сменить `POSTGRES_PORT` в `.env`. |

## 7. Упражнение

Добавьте в `pyproject.toml` runtime-зависимость `pydantic` командой `uv add pydantic`. Посмотрите `git diff` — что изменилось в `pyproject.toml` и `uv.lock`? Затем вручную поменяйте нижнюю границу версии в `pyproject.toml`, не трогая lock, и запустите `uv sync --locked` — убедитесь, что команда падает так же, как упала бы в CI. Откатите изменения.
